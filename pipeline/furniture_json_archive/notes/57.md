ACCESS/METHOD NOTES: ACCESS: www.westelm.co.uk is live and is a genuinely separate catalogue from westelm.com (S.N. 2). It is a NetSuite SuiteCommerce Advanced 2018.2 storefront (COMPID 3572911, siteid 28) run by the Williams-Sonoma UK business, on a different Akamai property from the US site, and the US site's access problems do not apply. No block was hit: plain curl with a desktop Chrome UA returned HTTP 200 for the homepage, and a Googlebot UA returned fully prerendered server-side HTML for every category page (a desktop UA gets only the SPA shell). The entire mega-nav was recovered from the homepage HTML; every category page in this file was fetched live and its breadcrumb read from that prerender. r.jina.ai was used only to read rendered PLP headers for verification. PLATFORM CORRECTION vs the assignment brief: this site does NOT run Constructor.io. Its product grid is rendered by SEARCHSPRING (Snap, siteId mrb1uc, taken from SC.ENVIRONMENT customizations.searchspring), which the theme drives with a background filter on ss_hierarchy built from the page breadcrumb. The native SuiteCommerce /api/items endpoint exists but is NOT what the page renders - for Table & Desk Lamps it returns 79 where the page shows 46 - so it was rejected outright. QTY VERIFICATION (Rule 1) - THE SITE'S OWN HEADER IS INFLATED BY EXACTLY 1: Searchspring pagination.totalResults does drive the site's 'N products' header (confirmed on 5 categories by r.jina.ai renders: 46, 40, 23, 7 and 3, all matching totalResults). But that total counts one injected merchandising banner tile as if it were a product. Proven three ways: (a) every category returns len(results) == totalResults - 1 with exactly one entry in merchandising.content.inline (a 'Limited Time Offer' sale banner); (b) the rendered Decorative Mirrors page says '7 products' and its grid contains exactly 6 product tiles, and the rendered Dinnerware Sets page says '3 products' against exactly 2 tiles; (c) a full catalogue enumeration returned 1,839 unique product uids against a reported total of 1,840, and its per-node leaf counts reproduce the -1 figure for every category in this file. qty is therefore the exhaustion-verified unique product count, and each evidence string also records the header value the site prints, so the orchestrator can switch to the header figure by adding 1 if it prefers the literal on-page number.
