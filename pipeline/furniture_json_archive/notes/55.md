## Prior Home-Decor pass (archive c58) status=partial
ACCESS/METHOD NOTES: ACCESS. crateandbarrel.com is behind Akamai Bot Manager. Direct fetch 403s; the working route is curl_cffi TLS impersonation, but NO single profile works reliably - the winning profile rotates and each fingerprint is burned after roughly one successful page load. chrome99 carried the homepage, safari18_0_ios the first listing pages, then safari17_0, chrome116, chrome131_android and chrome146 each took one page. A 44-profile round-robin at one request per 22-60s produced a ~15% hit rate at first and collapsed to ~1% once the workstation IP went hot; the IP block survived a 25-minute quiet period. Alternate routes all failed on this site: r.jina.ai returned a Cloudflare challenge on every attempt (shared/contended), translate.goog 403, WebFetch 403, HTTP/1.1 downgrade 403, referer + sec-fetch headers 403, IPv6 403, and session-cookie riding after a successful load gave zero extra pages. Sitemaps and /dist/js static assets are NOT protected: assets/sitemap-index.xml, sitemap-plp.xml (1,873 listing URLs) and sitemap-supercategory-and-spategory.xml (175 hub URLs) were served unchallenged and gave the whole category tree; the full mega-menu is also embedded in every page's HTML.

COUNTS. The authoritative number is the rendered listing header <div class="item-count" data-testid="item-count">N Items</div>. It was cross-checked three ways and agreed on every page fetched: it equals the container attribute data-num-results, equals the embedded state field "totalCount", and - on every category with fewer than 100 products - equals the exact number of "productId" entries in the page's own digitalData product array, which is a full exhaustion check because the page size is 100 (proved by the footer "Showing 100 of 516" on /lighting/). Verified exactly this way on sconces 82, wall mirrors 58, decorative mirrors 97, kids ceiling 30, kids wall-mounted 10, kids table lamps 32, kids floor lamps 9, kids night lights 11, kids mirrors 15, kids ceiling+wall 36, kids table+floor 41, desk lamps 72.

COUNT SOURCE REJECTED - Constructor.io. The site runs Constructor.io (key key_hfjoqZIKFQdxWaB6, browse/group_id/<id> on ac.cnstrc.com, entirely unprotected). Its total_num_results is NOT usable here: Lighting 517 vs rendered 516, Sconces 89 vs 82, Wall Mirrors 62 vs 58 (Ceiling Lighting 215 and Table+Floor Lamps 188 did match). Diffing the two product sets for Sconces showed 25 items the API returns that the PLP does not and 20 the PLP shows that the API does not, so it is a different index rather than an unfiltered superset - no filter can reconcile them. Constructor was used only to confirm the group tree.

SECOND COUNT SOURCE USED. Category hub pages of the "spategory" type render each child as a link reading "Shop All <name> (N)". /lighting/lighting-by-room/ and /kids/lighting-by-room/ published all their children's counts this way, and those 11 rows are sourced from there - it is the site's own published number for that exact child URL. Product-type hubs (decorative-mirrors, drinkware, dinnerware, serveware) render as ordinary listing pages instead and carry no child counts.

RULE 0. Every room-based lighting node was extracted rather than skipped: Bedroom, Dining Room, Bathroom, Living Room, Kitchen, Entryway and Outdoor lighting on the main site, plus Kids Bedroom, Nursery, Playroom and Study Room lighting. All mirror types are included, including Bath Mirrors (which sits inside the Bath department) and Kids Mirrors. Room/type overlap is real and documented: Crate & Barrel publishes both a fixture-type tree (Ceiling Lighting, Table & Floor Lamps, Wall Sconces) and a room tree (Lighting by Room) over the same 516-product Lighting catalogue, so the same fixture appears under both branches. Both are emitted under their own parent rows per Rule 0.6. Kids lighting and kids mirrors likewise overlap the Crate&kids department only, not the main-site rows.
