ACCESS: robots.txt checked FIRST -- no Claude-specific disallow (no ClaudeBot / Claude-User / Claude-SearchBot / Claude-Web / anthropic tokens; only Pinterest crawl-delays and standard account/cart/checkout/_next-static disallows), so clear to proceed. Plain direct fetch (desktop Chrome UA) returned HTTP 200 on robots.txt, sitemap.xml and every category page -- no WAF/challenge, no Rule 2 escalation needed for the storefront. LOCALE: robots.txt confirms eq3.com splits into /ca/en/, /ca/fr/ and /us/en/. The roster lists Canada so the ENGLISH CANADIAN storefront (/ca/en/) was used throughout, and every link below is a /ca/en/ URL. A US split does exist and is MATERIAL, not cosmetic -- spot-checked three nodes: Mirrors CA 13 vs US 8, Pendant Lamps CA 75 vs US 57, Decoration CA 29 vs US 16. The Canadian catalogue is consistently the larger one; had /us/en been used the qty would have been wrong on every row. PLATFORM: Next.js SSR app. api.eq3.com (the XHR backend, POST /product-instance/search) is hard-403 to every access route tried -- plain curl with Origin/Referer/X-EQ3-DeviceId headers, and a 10-profile curl_cffi impersonation sweep (chrome131/124/120/116/110/107, edge101, safari17_0/15_5, firefox133) all returned 403, so the API was NOT usable. Side door used instead per Rule 2: the server-rendered __NEXT_DATA__ blob on each category page embeds the React-Query dehydrated state including the full /product-instance/search response -- its own "count" field plus the product objects. STALE-SITEMAP TRAP (important): sitemap.xml is out of date and lists retired nodes. Slugs /category/lighting/lighting/*, /category/outdoor/*, /category/rugs/* and /accents/sculptures-wall-art no longer resolve -- their SSR query silently falls back to a parameterless catalogue-wide search returning count=1066 (the entire site) or to the bare parent subcategory. Taking those numbers at face value would have produced grossly inflated qty. The site's OWN live nav (the /site-navigation/menu-summary payload: 10 categories, 36 subcategories, 140 product lines) was used as the authoritative taxonomy instead, which shows Lighting and Rugs are now SUBCATEGORIES under Accessories (/category/accessories/lighting/... , note the live slug is lowercase 'table-and-desk-lamps'), that Outdoor and Sculptures & Wall Art are retired outright, and that the sitemap itself is only partial (it lists 3 mirror products against a true count of 13), so the sitemap was rejected as a counting source. COUNT VERIFICATION (Rule 1): every qty below is EXHAUSTION-VERIFIED, not a bare trust of the platform total. The category route accepts a ?page=N query param that makes the SSR prefetch N pages of 24 products; for every node with count>24 the page was re-fetched at ceil(count/24)+1 -- deliberately one page PAST the boundary -- and the unique product IDs harvested from the payload were counted. Unique-ID count equalled the reported count on 25 of 25 nodes tested, with zero mismatches, so EQ3's count field is exact here (contrary to the Shopify/Magento inflation pattern seen elsewhere on this project). Nodes with count<=24 are self-verifying since the first SSR page returns the whole set. RULE 0 GAINS: Lighting is buried as a subcategory of Accessories, not a top-level node, and was reached only via the live nav after the sitemap's /lighting/lighting/* path proved retired -- all 4 fixture lines (163 rows, 159 unique products) recovered.
