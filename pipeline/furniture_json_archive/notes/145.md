ACCESS/METHOD NOTES: Galeries Lafayette is a French department store; the Maison (Home) department sits under /c/maison-et-loisirs/maison on an Angular SPA (Spartacus/SAP Commerce Cloud, base site 'gl-fr', backend sapapi.galerieslafayette.com). ACCESS: robots.txt (fetched via curl_cffi impersonate=safari17_0/safari15_5/firefox133 after a warm-up GET of the homepage to obtain a Cloudflare __cf_bm cookie) shows no Claude/bot-specific Disallow -- only the generic User-agent:* group with narrow /search/ param exclusions; a plain requests UA gets 403 'Acces restreint' from Cloudflare, but the impersonated TLS profiles pass. STRUCTURE: full category tree recovered from siteMap/Category-fr-EUR.xml (526 URLs under maison-et-loisirs/maison), confirming the site organizes Maison into art-de-la-table, culinaire, decoration-de-la-maison, electromenager, jardin, linge-de-maison, literie, luminaires, mobilier, rangement -- only luminaires (lighting), the mirrors/clocks/wall-decor/decor-object nodes under decoration-de-la-maison, and the dinnerware/glassware nodes under art-de-la-table are in scope per the include/exclude rules; culinaire, electromenager, jardin, linge-de-maison, literie, mobilier, rangement, rideaux/tapis (curtains/rugs, except the curtain-rod hardware node), cuisine-nomade, couverts (cutlery), vins-et-cocktails bar tools, bougies-parfumees/senteurs (scented candles/home fragrance), and decorations-festives (holiday) were excluded. 'plantes' under objets-de-decoration was excluded as presumed artificial/faux plants (explicit exclusion; could not verify product titles because search is blocked, see below). QTY: exhaustively attempted Rule 2's toolkit against the OCC API (base https://sapapi.galerieslafayette.com/occ/v2/gl-fr) -- discovered the real endpoint config in the JS bundle (products/search with query=':relevance:allCategories:<code>' DSL, plus a distinct categories/{code}/products REST resource also referenced in the bundle), obtained real internal category codes (e.g. clswebmainv21nv33nv41nv58 for Plafonniers d'interieur, clswebmainv21nv33nv41nv57 for Lustres/suspensions, clswebmainv21nv36nv43nv54 for Vases/cache-pots) by looking up real sample products' categories(FULL) field, and even obtained a working OAuth client_credentials bearer token (client_id=mobile_android) from /authorizationserver/oauth/token -- but products/search ignores every query value tested (valid category codes, brand facets, plain free-text keywords, garbage strings all alike) and always returns an identical unfiltered default: totalResults=29600, empty breadcrumbs, currentQuery reset to ':recommended-asc', same 3 generic fashion/home products first. This held across 3 TLS impersonation profiles, with/without the bearer token, with/without Referer matching the real category URL, and with x-anonymous-consents set. The categories/{code}/products endpoint returns 404 UnknownResourceError for every code tested (not exposed at the gateway). Direct HTML fetch of any /c/ URL only returns the 6.3KB Angular SPA shell (no SSR/prerendering for our fingerprints); WebFetch got 403; r.jina.ai got a Cloudflare challenge page; translate.goog returns the same bare SPA shell. Browser automation is prohibited by Rule 2.
