ACCESS/METHOD NOTES: ACCESS: direct fetch worked throughout, no blocking. https://www.oka.com/uk 301s to https://www.oka.com/ (UK is the default locale, GBP), so canonical links use the bare www.oka.com/collections/ paths. Site is Shopify but the product grid is rendered entirely client-side by Graphene HC (Advanced Commerce): server HTML carries only 4 placeholder tiles and the 'Showing <n> of <N> items' header is empty until JS runs, so no count is readable from raw HTML or WebFetch. COUNT METHOD: located the grid's data source at POST https://okashopify-1.store-uk1.advancedcommerce.services/api/js/query (template id 'category', theme 38caf17c88c5431c932b42cdc117b64e). The collection is resolved server-side from the X-Referer header, not the body - without that header the API silently returns the whole 1637-product catalogue with header.category_id=null, which was a real trap. Every qty is elements.category.products.meta.product_count, the exact field the theme writes into the rendered [data-graphene-hc-el='pagination-total'] header. VERIFICATION: because the brief warns that reading the code proves only what the page renders, each count was also proved by exhaustion - paged the API with page_number until empty and counted unique item.id values. lighting 198 (60/60/60/18 then page 5 empty), mirrors 34, lampshades 76, table-lamps 74, tableware 116, homeware-accessories 242 - all matched product_count exactly, and children were confirmed as proper subsets of parents by product-ID set comparison. CROSS-CHECK NOTE: Shopify /collections/<handle>/products.json enumerates HIGHER (mirrors 54 vs 34, lighting 270 vs 198, crockery 66 vs 49) because OKA sells each size/colour as its own Shopify product and Graphene collapses them into one grid tile via size_related_products. The rendered grid figure is the site's own reported number, so the Graphene figure is used - consistent with the standing rule that only the rendered header is authoritative.
