ACCESS/METHOD NOTES: RULE 3 / AUTHENTICITY: genuine corporate storefront of Cello World Limited (BSE/NSE-listed Indian houseware manufacturer). /pages/contact-us gives the real corporate office - 'Cello World Limited, Cello House, Corporate Avenue, Sonawala Industry Estate, Goregaon (E), Mumbai 400063' - and site meta keywords name 'Cello World Limited'. Not a reseller/impersonation site (S.N. 109 Alinea precedent checked). Catalogue is LIVE, not retired or redirected. ACCESS ROUTE: plain direct curl with a desktop UA, first try, no WAF, no bypass needed. www.celloworld.com 301s to https://celloworld.com. robots.txt has ONE generic 'User-Agent: *' group (Allow: / plus Disallow of /api/*, /account/*, /cart/*, /*.json$, /*/order/*) - NO ClaudeBot/Claude-User/Claude-SearchBot/Claude-Web disallow, so the Amazon/Home24 precedent does not apply. The Disallow of /*.json$ and /api/* was respected: no products.json and no internal API endpoint was called; every number below comes from the ordinary HTML of the category page itself. LANGUAGE: site renders 100% in English natively (INR pricing, en lang attribute); no Hindi or regional-language category names anywhere, so no translation was needed. PLATFORM & COUNT METHOD (RULE 1): headless Shopify behind a Next.js/Vercel front end (product IDs are gid://shopify/Product/..., images on cdn.shopify.com/s/files/1/0801/3922/3334). The category pages render NO 'N products' header at all, so there is no site-reported count string to quote. Instead every category page server-renders its complete product list into the React Server Component flight payload as 'initialProducts' with a Shopify pageInfo. Every category checked came back with pageInfo.hasNextPage=false, i.e. the payload is the whole collection, so each qty is an exhaustive enumeration of DISTINCT gid://shopify/Product IDs - not an API total. VARIANT-INFLATION TRAP CONFIRMED AND AVOIDED: the same payload carries 'initialFilters.price.count', which looks like a product total but is a VARIANT total. Proof: /collections/all-products enumerates 179 distinct products while price.count says 577; /collections/tableware enumerates 27 products vs count 48; /collections/glassware 9 vs 15; /collections/kidzbee-dinner-set 7 vs 35. Had that field been trusted, every qty would have been 2-5x too high (same class of error as the Design Public Algolia nbHits case). All qty values below are the deduplicated distinct-product counts. CATALOGUE SIZE CROSS-CHECK: the whole D2C site is only 179 live products (/collections/all-products, hasNextPage=false). The site's own sitemap.xml lists 223 /products/ URLs, but the 44 extras are stale - spot-checked https://celloworld.com/products/solitaire-opalware-dinner-set-ruby-nw, which renders the 404 page. So 179 is the real live catalogue and the leaf counts below are consistent with it. SCOPE / STRUCTURE: the mega menu has 11 top-level nodes - Hydration, Personalize, Tableware, Kitchen, Tiffin Boxes, Cookware, Appliances, Cleaning Essential, Kidzbee, Porcelain, Glassware (plus a Gifting node whose collections are all EMPTY, and which would be excluded as a gift guide regardless).
